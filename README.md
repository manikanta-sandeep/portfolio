# Portfolio Application

Personal portfolio for sandeeppuppala.com: a React + Vite site with a small Node.js API and SQLite database for blog view counts, the contact inbox, and an admin area where all content is edited.

## Architecture

| Part | Where | What |
| --- | --- | --- |
| Website | `src/` | React single-page app (public pages + `/admin`) |
| API | `server/` | Express on port 3001: content, view counts, contact messages, login, uploads, sitemap |
| Database | `server/data/portfolio.db` (dev), `/var/lib/portfolio` (prod) | SQLite: profile, sections, posts, views, messages, admin users, sessions, site analytics (cookieless; see `server/src/analytics.js`) |
| Shared schema | `shared/contentSchema.js` | Field definitions used by both the admin forms and API validation |
| Seed content | `src/data/` | Loaded into an empty database on first start, and the fallback if the API is unreachable |

## Local Development

1. `npm install` (website) and `npm --prefix server install` (API)
2. `npm run create-admin -- <username>` to create your admin login (asks for a password, 10+ characters; run it again to reset the password)
3. `npm run dev`

`npm run dev` starts the API and the website together and opens the browser; Vite forwards `/api`, `/uploads`, and `/sitemap.xml` to the API. Use `npm run dev:web` or `npm run dev:api` to start just one.

The first API start creates `server/data/portfolio.db` from `src/data/`. Delete that folder to start over from the seed content.

## Admin Area

Sign in at `/admin` (also linked as "Sign in" in the footer). From there you can:

- Write, edit, publish/unpublish, feature, and delete blog posts (Markdown with live preview; images and covers can be uploaded)
- Edit your profile (name, headline, photo, summary, interests, links, resume)
- Edit every section: experience, education, skills (levels show proficiency bars), projects, research, teaching, activities, achievements, certifications; add, remove, and reorder entries
- Read and manage contact form messages
- Keep private notes and files (Notes & Files) to move text and files between your devices. Files are stored in `DATA_DIR/drive`, up to 100 MB each and 5 GB in total, and only download while signed in. They are not part of the daily backup.
- See post view counts and change your password

## Blog Views

Each post counts at most one view per visitor per day. Visitors are identified by a salted hash of IP and browser, so no IP addresses are stored. Your own visits while signed in are not counted.

## Site Structure

| Route | Page |
| --- | --- |
| `/` | Bio: summary, education, experience, featured projects, interests |
| `/experience` | Work history and education |
| `/skills` | Featured skills, skills by category, overview stats |
| `/projects`, `/projects/:id`, `/research/:id` | Project and research list and detail pages |
| `/extracurriculars` | Teaching, activities, achievements, certifications |
| `/blog` | Latest-post hero, featured posts, category/tag filters (`?category=`, `?tag=`), pagination (`?page=`) |
| `/blog/:id` | Post with reading progress, table of contents, share buttons, previous/next and related posts |
| `/contact` | Contact form |
| `/search?q=` | Client-side search across pages, projects, posts, experience, and skills |

Site-wide: sticky header with search (`/` or Ctrl/Cmd+K), dark/light theme toggle (saved per browser), mobile menu, floating contact widget, toast notifications, and scroll-reveal animations.

## Content Editing

Edit content in the admin area. `src/data/profileData.js` and `src/data/blogData.js` are only the initial seed (and the static fallback); changing them does not affect a database that already exists.

## Oracle Cloud Deployment (sandeeppuppala.com)

The site is served by nginx on an Oracle Cloud Always Free VM. Files:

- `deploy/nginx/sandeeppuppala.com.conf`: nginx site (SPA fallback, caching, www → apex redirect)
- `deploy/setup-server.sh`: one-time VM setup (nginx, Node.js, firewall, API service, backups, HTTPS certificate)
- `deploy/portfolio-api.service`: systemd service that runs the API as a locked-down `portfolio` user
- `deploy/portfolio-backup`: daily backup of the database and uploads to `/var/backups/portfolio` (14 days kept)
- `.github/workflows/deploy-oracle.yml`: on every push to `main`, builds the site, uploads it and the API, and restarts the API

### 1. Create the VM

1. Oracle Cloud Console → Compute → Instances → Create instance.
2. Image: **Canonical Ubuntu 24.04**. Shape: **VM.Standard.A1.Flex** (Ampere, Always Free) or **VM.Standard.E2.1.Micro**.
3. Add your SSH public key (or let Oracle generate a key pair and download the private key).
4. Note the instance's **public IP address**.

### 2. Open ports 80 and 443 in Oracle's network

Networking → Virtual Cloud Networks → your VCN → Security Lists → Default Security List → Add Ingress Rules:

| Source CIDR | Protocol | Destination port |
| --- | --- | --- |
| `0.0.0.0/0` | TCP | 80 |
| `0.0.0.0/0` | TCP | 443 |

(The VM's own iptables firewall is opened by `setup-server.sh`.)

### 3. Point the domain at the VM

At your domain registrar's DNS settings for `sandeeppuppala.com`:

| Type | Name | Value |
| --- | --- | --- |
| A | `@` | VM public IP |
| A | `www` | VM public IP |

Remove any parking-page A/CNAME records for `@` or `www`. Check propagation with `nslookup sandeeppuppala.com`.

### 4. Set up the server (once)

```bash
ssh ubuntu@<VM public IP>
git clone https://github.com/manikanta-sandeep/portfolio.git
cd portfolio/deploy
sudo bash setup-server.sh <your email>
```

The email only receives certificate expiry notices. Certificates renew automatically.

### 5. Connect GitHub Actions

Create a deploy key pair on your computer (no passphrase) and authorize it on the VM:

```bash
ssh-keygen -t ed25519 -f oracle_deploy -N "" -C "github-actions-deploy"
ssh-copy-id -i oracle_deploy.pub ubuntu@<VM public IP>   # or append it to ~/.ssh/authorized_keys on the VM
ssh-keyscan -H <VM public IP>                             # output goes in ORACLE_KNOWN_HOSTS
```

In GitHub → repository Settings → Secrets and variables → Actions, add:

| Secret | Value |
| --- | --- |
| `ORACLE_HOST` | VM public IP |
| `ORACLE_USER` | `ubuntu` |
| `ORACLE_SSH_KEY` | contents of `oracle_deploy` (the private key) |
| `ORACLE_KNOWN_HOSTS` | output of `ssh-keyscan -H <VM public IP>` |

Then push to `main` (or run the workflow from the Actions tab) and visit https://sandeeppuppala.com.

### 6. Create your admin login (once, after the first deploy)

```bash
ssh ubuntu@<VM public IP>
sudo -u portfolio env DATA_DIR=/var/lib/portfolio node /opt/portfolio/server/src/cli/create-admin.js <username>
```

Then sign in at https://sandeeppuppala.com/admin. Deploys never touch the database, so your edits, posts, views, and messages persist. Download backups from `/var/backups/portfolio` from time to time to keep a copy off the VM.

## GitHub Pages Deployment

Workflow file:

- `.github/workflows/deploy-pages.yml`

Steps:

1. Push to `main`
2. In GitHub repository settings, enable Pages and set source to GitHub Actions
3. Workflow builds with Node 20 and deploys `dist/`

## Base URL Note

The build uses relative asset paths (`base: "./"`) and detects at runtime whether it is served from the domain root or `/portfolio`, so it works as either a user site or a project site.

GitHub Pages has no SPA fallback, so `public/404.html` redirects deep links such as `/portfolio/blog/my-post` to the app with the path in the query string, and `restoreRedirectedPath()` in `src/lib/paths.js` restores the real URL before the router starts.
